# LEX:2026.0.2.1 Implementation Guide

## Overview
This repository contains a complete implementation of the LEX:2026.0.2.1 (LDBC Extended GQL Schema) specification for property graph schema management. LEX:2026.0.2.1 is the latest build of the LEX:2026.0.2 standard, featuring enhanced value types, embedded canonical type definitions, and comprehensive cross-system type mappings.

## New in LEX:2026.0.2.1

### Enhanced JSON Schema with Embedded Type Definitions
- **Canonical Value Types**: Complete `$defs` section with all 14 canonical types
- **Four-Way Mappings**: Each type includes data/gql/sql/canonical cross-references
- **Self-Documenting**: JSON Schema now contains complete type system documentation
- **Validation Ready**: Enables programmatic validation of canonical type usage

### Validated Canonical Type Usage
- **YAML Examples**: All schema examples use only the 14 canonical types
- **Type Consistency**: INTEGER (64-bit), FLOAT (double precision), STRING, BOOLEAN, temporal types, LIST, RECORD, VECTOR, JSON
- **Cross-System Compatibility**: Guaranteed compatibility across GQL, SQL Foundation, and Cypher systems

## Key Features Demonstrated

### 1. Canonical Value Type System
LEX:2026.0.2 introduces a canonical value type system as the default, featuring:
- **Atomic Types**: `BOOLEAN`, `STRING`, `INTEGER`, `FLOAT`
- **Temporal Types**: `DATE`, `TIME`, `LOCAL DATETIME`, `ZONED DATETIME`
- **Structured Types**: `LIST`, `RECORD` with nested compositions
- **Semi-Structured Types**: `JSON` for document storage
- **Nullable Parameters**: All types support `nullable: true/false`

### 2. Enhanced Constraint System
- **Unique Constraints**: `UNIQUE` with `uniqueKeyComponentPropertyNames`
- **Mandatory Properties**: Handled via `nullable: false` in value type definitions
- **Structured Constraint Rules**: Proper `subject` and constraint pattern definitions

### 3. Graph Instance Format
- **Embedded Schemas**: Graph instances can embed their type definitions
- **Storage Schema Integration**: Placeholder for GraphAr and other storage formats
- **Instance-Level Constraints**: Constraints defined at the graph instance level

### 4. Heterogeneous Edge Endpoints
- **Multiple Source Types**: Edges can connect different node type combinations
- **Type Identifying Labels**: Use `typeIdentifyingLabels` for union-type endpoints

## Running Validation Scripts

### Prerequisites
```bash
# Install required Python packages
pip install jsonschema pyyaml
```

### Schema Validation Scripts

#### FinBench Schema Validation
```bash
# Validate FinBench schema against LEX:2026.0.2.1 JSON Schema
cd tests
python validate_finbench_lex_0_2_1_schema.py
```
**What it does**: Validates the FinBench schema structure, canonical value types, constraints, and node/edge type definitions against the LEX:2026.0.2.1 specification with embedded type definitions.

#### SNB Schema Validation
```bash
# Validate Social Network Benchmark schema
cd tests
python validate_snb_lex_0_2_1_schema.py
```
**What it does**: Validates the SNB schema with its social network entities (Person, Post, Comment, Forum, etc.) and relationship types using canonical value types.

#### Graph Instance Validation
```bash
# Validate FinBench graph instance with embedded schema
python validate_finbench_graph_instance.py
```
**What it does**: Validates the complete graph instance format including embedded schema, instance constraints, and storage schema placeholders.

### Catalog Validation Scripts

#### Standard Catalog Validation (with IRI)
```bash
# Validate catalog with IRI addressing
cd tests
python validate_catalog_example_0_2_1.py
```
**What it does**: Validates hierarchical catalog structure with IRI-based object addressing and cross-references using LEX:2026.0.2.1 schema.

#### Simplified Catalog Validation (without IRI)
```bash
# Validate catalog without IRI requirements
cd tests
python validate_catalog_no_iri_0_2_1.py
```
**What it does**: Validates catalog structure using simpler locally qualified names without IRI addressing requirements using LEX:2026.0.2.1 schema.

## Key Improvements in 0.2.1

1. **Embedded Type Definitions**: JSON Schema now includes complete canonical value type definitions
2. **Four-Way Type Mappings**: Universal VTS ↔ GQL ↔ SQL ↔ Canonical cross-references in schema
3. **Self-Validating Schema**: Type usage can be programmatically validated against canonical definitions
4. **Enhanced Documentation**: Complete type system interoperability documented in schema
5. **Validated Examples**: All YAML examples confirmed to use only canonical types
6. **Build Versioning**: Introduced build numbers (0.2.1) for iterative delivery on minor versions

## Key Improvements in 0.2

1. **Canonical Value Types**: Standardized type system with consistent nullable parameters
2. **Graph Instances**: New format for representing actual graph data with embedded schemas
3. **Enhanced Constraints**: Structured constraint definitions with proper rule syntax
4. **Flexible Catalogs**: Support for both IRI-based and simple addressing schemes
5. **Storage Integration**: Placeholders for GraphAr and other storage format integration
6. **Heterogeneous Edges**: Support for edges connecting multiple node type combinations
