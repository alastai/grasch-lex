## Key Changes from 0.2.1

2. **Minimum Label Defaults**: Changed from 0 to 1

1. **Subtyping**: Types can declare supertypes
2. **Imports**: Modularization via `$ref`
3. **Type Interpretation**: Control validation behavior
4. **Extension Interpretation**: Control type extensibility
5. **File References**: Catalog entries can reference files

## Migration Guide

### From 0.2.1 to 0.3.2

**Step 1**: Ensure all types have labels
```yaml
# Before (0.2.1) - This was valid
nodeTypes:
  - nodeTypeIdentifier:
      nodeTypeIndex: 0
    labels: []  # ❌ No longer valid

# After (0.3.2) - Required
nodeTypes:
  - nodeTypeIdentifier:
      typeLabel: "MyType"
    labels: ["MyType"]  # ✅ At least one label
```

**Step 2**: Update minimum label constraints
```yaml
graphType:
  nodeTypeMinimumLabels: 1  # Changed from 0
  edgeTypeMinimumLabels: 1  # Changed from 0
```

**Step 3** (Optional): Use new features
- Add `supertypes` for inheritance
- Use `$ref` for imports
- Set `typeInterpretation` for validation control

## Implementation Notes

### Type Identification
- **Preferred**: `typeLabel` (single label as type name)
- **Supported**: `typeIdentifyingLabels` (set of labels)
- **Supported**: Type index (for anonymous types)
- **Examples**: All use `typeLabel` as preferred method

### Labels vs Type Labels
- **Labels**: At least one required (mandatory in 0.3)
- **Type Label**: Optional, but when used, must be in labels set
- **Examples**: Focus on identified types with type name labels

### Backward Compatibility
- ✅ Schemas with labels from 0.2.1 work in 0.3.2
- ❌ Schemas without labels from 0.2.1 fail in 0.3.2
- ✅ New features are optional and backward compatible
