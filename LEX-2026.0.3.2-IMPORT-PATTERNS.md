# LEX:2026.0.3.2 Import Patterns

This document describes all supported import patterns in LEX:2026.0.3.2 schemas.

## Import Levels

### Level 1: GraphType Defaults

Import default settings for the entire graph type:

```yaml
graphType:
  import: "lex-2026.0.3.2-graph-type-defaults.yaml"
  nodeTypes: [...]
  edgeTypes: [...]
```

### Level 2: Entire Type Arrays

Import all node types or all edge types:

```yaml
graphType:
  nodeTypes:
    import: "all_node_types.yaml"
  
  edgeTypes:
    import: "all_edge_types.yaml"
```

### Level 3: Individual Types Within Arrays

Import individual types mixed with inline definitions:

```yaml
graphType:
  nodeTypes:
    - nodeType:
        typeLabel: Person
        implies: {...}
    
    - import: "organisation_hierarchy.yaml"
    
    - nodeType:
        typeLabel: Tag
        implies: {...}
```

### Level 4: Within Interpretation Descriptors

Import types within `allowSubtypesOf`:

```yaml
graphType:
  allowSubtypesOf:
    nodeTypes:
      - import: "company_hierarchy.yaml"
    
    abstractSupertypes:
      nodeTypes:
        - import: "message_hierarchy.yaml"
```

## Complete Example

```yaml
pathName: "/examples/multi-level-imports"

graphType:
  # Level 1: Import defaults
  import: "defaults.yaml"
  
  # Level 3: Mix inline and imported
  nodeTypes:
    - nodeType:
        typeLabel: Person
        implies:
          propertyTypes:
            - name: id
              valueType: INTEGER
              notNull: true
    
    - import: "organisation_types.yaml"
    - import: "place_types.yaml"
  
  # Level 3: Mix inline and imported
  edgeTypes:
    - edgeType:
        typeLabel: KNOWS
        implies:
          propertyTypes: []
        direction: UNDIRECTED
        firstEndpointNodeType:
          typeLabel: Person
        secondEndpointNodeType:
          typeLabel: Person
    
    - import: "relationship_types.yaml"
  
  # Level 4: Import within interpretation descriptors
  allowSubtypesOf:
    abstractSupertypes:
      nodeTypes:
        - import: "message_hierarchy.yaml"
```

## Import Resolution

1. **Relative Paths**: Import paths are relative to the importing file's directory
2. **Recursive Imports**: Imported files can themselves contain imports
3. **Merge Semantics**: 
   - Defaults are merged (imported values can be overridden)
   - Arrays are concatenated (imported items are added to inline items)
4. **Validation**: All imports are resolved before schema validation

## Best Practices

1. **Modular Hierarchies**: Use separate files for type hierarchies (Message, Organisation, Place)
2. **Shared Defaults**: Keep common graph type settings in a shared defaults file
3. **Domain Grouping**: Group related types in domain-specific files
4. **Clear Naming**: Use descriptive filenames with LEX version prefix

## Supported Patterns Summary

| Level | Location | Pattern | Example |
|-------|----------|---------|---------|
| 1 | graphType | `import: "file.yaml"` | Defaults |
| 2 | nodeTypes/edgeTypes | `import: "file.yaml"` | All types |
| 3 | Within arrays | `- import: "file.yaml"` | Individual types |
| 4 | allowSubtypesOf | `- import: "file.yaml"` | Hierarchy groups |

All patterns can be mixed and nested as needed for maximum flexibility.
