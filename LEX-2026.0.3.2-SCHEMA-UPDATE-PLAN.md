## Schema Updates Needed

### Priority 1: Core New Syntax (Required for most examples)

#### 1. New Edge Type Syntax
**Current:** Uses `direction`, `firstEndpointNodeType`, `secondEndpointNodeType`
**New:** Two patterns:
```yaml
# Directed
directed:
  from: NodeTypeRef
  via: string  # or arc:
  to: NodeTypeRef

# Undirected  
undirected:
  between: NodeTypeRef
  via: string  # or arc:
  and: NodeTypeRef
```

**Schema Changes:**
- Add `directed` object with `from`, `via`/`arc`, `to` properties
- Add `undirected` object with `between`, `via`/`arc`, `and` properties
- Make old syntax and new syntax alternatives in `oneOf`

#### 2. Index-Based Node Type References
**Current:** Only supports `{typeLabel: "Name"}`
**New:** Also supports `{index: 0}` for forward references

**Schema Changes:**
- Update NodeTypeReference to accept either:
  - `{typeLabel: string}`
  - `{index: integer}`
  - `{typeLabels: [string]}`  # multi-label

#### 3. Import Support in GraphType
**Current:** GraphType doesn't support `import` field
**New:** Can import defaults/base types

**Schema Changes:**
- Add `import` as optional string property in GraphType
- Add `defaults` object for default values

### Priority 2: Type System Enhancements

#### 4. Finalization Keywords
**New syntax:**
```yaml
# Abstract type (cannot be instantiated)
abstract:
  nodeType: {...}

# Abstract supertype (for type interpretation)
abstractSupertype:
  nodeType: {...}

# Sealed hierarchy (closed set of subtypes)
sealed:
  nodeTypes: [...]

# Final type (cannot be extended)
final:
  nodeType: {...}
```

**Schema Changes:**
- Add wrapper objects: `abstract`, `abstractSupertype`, `sealed`, `final`
- Update NodeType/EdgeType arrays to accept these wrappers

#### 5. Type Extension Syntax
**Current:** Uses `implies: {supertypes: [...]}`
**New:** Also supports `extends` with `adding`

```yaml
nodeType:
  typeLabel: Manager
  extends: Employee  # or extends: [Employee, Person]
  adding:
    propertyTypes: [...]
```

**Schema Changes:**
- Add `extends` as alternative to `supertypes`
- Add `adding` object (same structure as `implies`)
- Make `extends`+`adding` and `implies`+`supertypes` alternatives

### Priority 3: Convenience Features

#### 6. Synonym Support
Allow multiple keywords for same concept:
- `via` / `arc` (edge label)
- `extends` / `supertypes`
- `from`/`tail`/`src`, `to`/`head`/`dst`/`dest`

**Schema Changes:**
- Use `oneOf` to accept synonyms

#### 7. Graph Type Defaults
Support for default configuration values:
```yaml
graphPreferredName: "GRAPH"
nodeTypeMinimumLabels: 1
# etc.
```

**Schema Changes:**
- Add GraphTypeDefaults definition
- Allow as standalone document type
