# LEX:2026.0.2 Implementation Guide

## Overview
This repository contains a complete implementation of the LEX:2026.0.2 (LDBC Extended GQL Schema) specification for property graph schema management. LEX:2026.0.2 is the second version of the LEX standard, featuring enhanced value types, graph instances, and catalog management.

## Key Features Demonstrated

### 1. Canonical Value Type System
LEX:2026.0.2 introduces a canonical value type system as the default, featuring:
- **Atomic Types**: `BOOLEAN`, `STRING`, `INTEGER`, `FLOAT`
- **Temporal Types**: `DATE`, `TIME`, `LOCAL DATETIME`, `ZONED DATETIME`
- **Structured Types**: `LIST`, `RECORD` with nested compositions
- **Nullable Parameters**: All types support `nullable: true/false`

### 2. Enhanced Constraint System
- **Unique Constraints**: `UNIQUE` with `uniqueKeyComponentPropertyNames`
- **Mandatory Properties**: Handled via `nullable: false` in value type definitions
- **Structured Constraint Rules**: Proper `subject` and constraint pattern definitions

### 3. Graph Instance Format
- **Embedded Schemas**: Graph instances can embed their type definitions
- **Storage Schema Integration**: Placeholder for GraphAr and other storage formats
- **Instance-Level Constraints**: Constraints defined at the graph instance level

### 4. Heterogeneous Edge Endpoints
- **Multiple Source Types**: Edges can connect different node type combinations
- **Type Identifying Labels**: Use `typeIdentifyingLabels` for union-type endpoints

## Running Validation Scripts

### Prerequisites
```bash
# Install required Python packages
pip install jsonschema pyyaml
```

### Schema Validation Scripts

#### FinBench Schema Validation
```bash
# Validate FinBench schema against LEX:2026.0.2 JSON Schema
python validate_finbench_lex_0_2_schema.py
```
**What it does**: Validates the FinBench schema structure, value types, constraints, and node/edge type definitions against the LEX:2026.0.2 specification.

#### SNB Schema Validation
```bash
# Validate Social Network Benchmark schema
python validate_snb_lex_0_2_schema.py
```
**What it does**: Validates the SNB schema with its social network entities (Person, Post, Comment, Forum, etc.) and relationship types.

#### Graph Instance Validation
```bash
# Validate FinBench graph instance with embedded schema
python validate_finbench_graph_instance.py
```
**What it does**: Validates the complete graph instance format including embedded schema, instance constraints, and storage schema placeholders.

### Catalog Validation Scripts

#### Standard Catalog Validation
```bash
# Validate catalog with IRI addressing
python validate_catalog_example.py
```
**What it does**: Validates hierarchical catalog structure with IRI-based object addressing and cross-references.

#### Simplified Catalog Validation
```bash
# Validate catalog without IRI requirements
python validate_catalog_no_iri.py
```
**What it does**: Validates catalog structure using simpler locally qualified names without IRI addressing requirements.

### Expected Output
All validation scripts will output:
- ✅ **Success**: "Validation successful!" with schema details
- ❌ **Failure**: Detailed error messages showing validation issues

## Key Improvements in 0.2

1. **Canonical Value Types**: Standardized type system with consistent nullable parameters
2. **Graph Instances**: New format for representing actual graph data with embedded schemas
3. **Enhanced Constraints**: Structured constraint definitions with proper rule syntax
4. **Flexible Catalogs**: Support for both IRI-based and simple addressing schemes
5. **Storage Integration**: Placeholders for GraphAr and other storage format integration
6. **Heterogeneous Edges**: Support for edges connecting multiple node type combinations
