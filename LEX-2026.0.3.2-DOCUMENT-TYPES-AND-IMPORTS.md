# LEX-2026.0.3.2 Document Types and Import Mechanism

## Overview

This document defines the three top-level YAML document types supported by LEX-2026.0.3.2 and the import mechanism that allows modular composition of schema definitions. This specification must be enforced by the JSON Schema.

## Import Mechanism Principles

### General Rules

1. **Inline or Import**: Elements marked as `# IMPORTABLE` can be defined inline OR by using `import: <filePath>`
2. **Mixed Mode**: An element can contain both an `import:` and additional inline content
3. **File Format Flexibility**: The imported file can be structured in two ways:
   - **With root element**: File starts with the element name (e.g., `graphType:` when importing into `graphType`)
   - **Without root element**: File contains only the children of the importing element

### Example

```yaml
# Importing element
graphSchema:
  graphType:
    import: graphType.yaml
    # Can also have inline content here
```

The imported file `graphType.yaml` can be either:

**Option 1 - With root:**
```yaml
graphType:
  defaults: ...
  nodeTypes: ...
```

**Option 2 - Without root:**
```yaml
defaults: ...
nodeTypes: ...
```

## Three Top-Level Document Types

### 1. graph: (Graph Instance Document)

```
graph:
  pathname: (required)
  graphSchema: (optional) # IMPORTABLE
  graphStorageSchema: (optional) # IMPORTABLE
```

**Description:** Represents a graph instance that may reference or embed a schema and storage configuration.

---

### 2. graphSchema: (Graph Schema Document)

```
graphSchema:
  pathname: (required)
  graphType: (required) # IMPORTABLE
    pathname: (optional - only present if graphType is imported)
    defaults: (required) # IMPORTABLE
    nodeTypes: (optional) # IMPORTABLE
    edgeTypes: (optional) # IMPORTABLE
```

**Key Constraints:**
- A `graphType` cannot exist as a standalone top-level document
- A `graphType` must always be contained within a `graphSchema`
- When `graphType` is imported, it may have a `pathname` property

---

### 3. catalog: (Catalog Document)

```
catalog:
  IRI: (required)
  directories: (optional, recursive) # IMPORTABLE
    name: (required)
    directories: (optional, recursive)
    graphReferences: (optional, only in leaf directories)
      name: (required)
      qualifiedName: (required)
      filePath: (optional)
    graphSchemaReferences: (optional, only in leaf directories)
      name: (required)
      qualifiedName: (required)
      filePath: (optional)
```

**Key Constraints:**
- `graphReferences` and `graphSchemaReferences` are metadata-only (not full definitions)
- References contain only: `name`, `qualifiedName`, and optional `filePath`
- References can **only exist in leaf-node directories** (directories without subdirectories)
- The hierarchical directory structure is for organization
- Actual graph/schema content is referenced via `filePath`, not embedded

---

## Summary of Importable Elements

The following elements support the `import:` mechanism:

1. **graph: graphSchema:** - Import entire graphSchema
2. **graph: graphStorageSchema:** - Import storage configuration
3. **graphSchema: graphType:** - Import entire graphType
4. **graphType: defaults:** - Import default values
5. **graphType: nodeTypes:** - Import node type definitions
6. **graphType: edgeTypes:** - Import edge type definitions
7. **catalog: directories:** - Import directory structures

---

## JSON Schema Requirements

The JSON Schema must enforce:

1. **Document Type Discrimination**: Use `oneOf` at the top level to distinguish between `graph:`, `graphSchema:`, and `catalog:` documents
2. **Import Support**: For each importable element, allow either:
   - Inline definition
   - `import: <string>` property
   - Both (mixed mode)
3. **Catalog Constraints**: 
   - Validate that `graphReferences` and `graphSchemaReferences` only appear in leaf directories
   - Ensure references contain only `name`, `qualifiedName`, and optional `filePath`
4. **GraphType Containment**: Ensure `graphType` cannot be a top-level document type
5. **Required vs Optional**: Enforce the required/optional nature of each property as specified above
