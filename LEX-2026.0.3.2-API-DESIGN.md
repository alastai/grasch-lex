# LEX:2026.0.3.2 API Design

## Overview

The LEX:2026.0.3.2 Python API provides interfaces and implementation classes for working with graph catalogs, schemas, and instances. All classes can be constructed from YAML specifications or specification fragments.

## Core Interfaces

### Primary Catalog Objects

1. **Catalog** - Hierarchical collection of graph schemas and graphs
2. **GraphSchema** - Structural graph type plus constraints
3. **Graph** - Graph instance with optional schema and storage

### Component Objects

4. **GraphType** - Node types, edge types, and their properties
5. **NodeType** - Node type definition with labels and properties
6. **EdgeType** - Edge type definition with direction and endpoints
7. **PropertyType** - Property definition with name and value type
8. **Constraint** - Constraint definition (KEY, UNIQUE, etc.)
9. **StorageSchema** - Storage configuration

## Construction from YAML

All implementation classes support construction from YAML:

```python
# From complete YAML file
catalog = CatalogImpl.fromYAML("catalog.yaml")

# From YAML string
schema_yaml = """
pathName: /benchmarks/ldbc/snb
graphType:
  nodeTypes: [...]
"""
schema = GraphSchemaImpl.fromYAMLString(schema_yaml)

# From parsed dict
schema_dict = yaml.safe_load(schema_yaml)
schema = GraphSchemaImpl.fromDict(schema_dict)
```

## Navigation API

### Catalog Navigation

```python
catalog = CatalogImpl.fromYAML("catalog.yaml")

# Access schemas
schemas = catalog.getGraphSchemas()
snb_schema = catalog.findGraphSchema("/benchmarks/ldbc/snb")

# Access graphs
graphs = catalog.getGraphs()
my_graph = catalog.findGraph("/production/social/user-prod")
```

### GraphSchema Navigation

```python
schema = catalog.findGraphSchema("/benchmarks/ldbc/snb")

# Access graph type
graph_type = schema.getGraphType()

# Access constraints
constraints = schema.getConstraints()
person_unique = schema.findConstraint("personIdUnique")
```

### GraphType Navigation

```python
graph_type = schema.getGraphType()

# Access node types
node_types = graph_type.getNodeTypes()
person_type = graph_type.findNodeType("Person")

# Access edge types
edge_types = graph_type.getEdgeTypes()
knows_type = graph_type.findEdgeType("KNOWS")
```

### Type Hierarchy Navigation

```python
# Get node type information
type_label = person_type.getTypeLabel()  # "Person" (singleton identifier)
labels = person_type.getLabels()  # ["Person"]
properties = person_type.getPropertyTypes()
supertypes = person_type.getSupertypes()  # [] for base types

# Get type label from identifier (Optional)
# Returns label if identifier is singleton, None otherwise
label = person_type.getTypeLabel()  # "Person" for identifier ["Person"]
label = multi_type.getTypeLabel()   # None for identifier ["Person", "Employee"]

# Check if abstract
is_abstract = message_type.isAbstract()  # True for abstract types

# Navigate subtypes
post_type = graph_type.findNodeType("Post")
post_supertypes = post_type.getSupertypes()  # ["Message"]
```

### Edge Type Navigation

EdgeType provides multiple synonym accessors with no canonical form. All accessors are equally valid:

```python
knows_edge = graph_type.findEdgeType("KNOWS")

# Edge type label accessors (all equivalent)
label = knows_edge.getVia()          # Returns "KNOWS"
label = knows_edge.getArc()          # Returns "KNOWS" (synonym)
label = knows_edge.getTypeLabel()    # Returns "KNOWS" (synonym)

# Direction check
is_directed = knows_edge.isDirected()      # True/False
is_undirected = knows_edge.isUndirected()  # True/False

# Source/first endpoint accessors (all equivalent for directed edges)
source = knows_edge.getFrom()    # Returns source node type
source = knows_edge.getTail()    # Synonym
source = knows_edge.getSrc()     # Synonym

# Target/second endpoint accessors (all equivalent for directed edges)
target = knows_edge.getTo()      # Returns target node type
target = knows_edge.getHead()    # Synonym
target = knows_edge.getDst()     # Synonym
target = knows_edge.getDest()    # Synonym

# Undirected edge endpoint accessors
first = collab_edge.getBetween()  # Returns first endpoint
second = collab_edge.getAnd()     # Returns second endpoint

# Properties
properties = knows_edge.getPropertyTypes()
supertypes = knows_edge.getSupertypes()  # For edge type hierarchies
```

**Synonym Groups:**
- **Edge label**: `getVia()`, `getArc()`, `getTypeLabel()`
- **Source endpoint**: `getFrom()`, `getTail()`, `getSrc()`
- **Target endpoint**: `getTo()`, `getHead()`, `getDst()`, `getDest()`
- **Undirected first**: `getBetween()`
- **Undirected second**: `getAnd()`

All accessors return the same values regardless of which keyword was used in the YAML. The implementation detects the actual keywords used but makes all synonyms available.

### Node Type Context

Node types can exist in two contexts:

**1. Isolated Node Types** - Defined in `nodeTypes:` but never referenced by any edge type:
```python
# These can exist as standalone nodes in the graph
tag_type = graph_type.findNodeType("Tag")
is_isolated = not any(
    edge.getFrom() == tag_type or edge.getTo() == tag_type 
    for edge in graph_type.getEdgeTypes()
)
```

**2. Edge-Only Node Types** - Defined inline within edge type endpoints:
```python
# These node types only exist in the context of edges
# They cannot exist as isolated nodes
owns_edge = graph_type.findEdgeType("OWNS")
property_type = owns_edge.getTo()  # Property type defined inline

# Property nodes can ONLY exist when connected via OWNS edge
# They cannot exist as isolated nodes in the graph
```

This distinction allows schemas to specify:
- Node types that can exist independently (isolated)
- Node types that must always be connected (edge-only inline definitions)

## Type Finalization and Sealing

### Final Types

A type marked as `final:` cannot be subtyped:

```python
# Check if a type is final
is_final = company_type.isFinal()  # True for final types

# Attempting to create a subtype of a final type is invalid
# This would be rejected by schema validation
```

**YAML Syntax:**
```yaml
- final:
    nodeType:
      typeLabel: Company
      extends: Organisation
```

### Sealed Hierarchies

A `sealed:` hierarchy is closed - all possible subtypes are enumerated:

```python
# Check if a type is part of a sealed hierarchy
is_sealed = place_type.isSealed()  # True for types in sealed hierarchies

# Get all types in the sealed hierarchy
sealed_types = place_type.getSealedHierarchy()  # [Place, Continent, Country, City]
```

**YAML Syntax:**
```yaml
- sealed:
    nodeTypes:
    - abstract:
        nodeType:
          typeLabel: Place
    - nodeType:
        typeLabel: City
        extends: Place
```

### Equivalence Rules

1. **sealed: ≡ final: on all leaf subtypes**
   - A sealed hierarchy implicitly makes all leaf (concrete) types final
   - `sealed: { Place, City, Country }` ≡ `Place + final: City + final: Country`

2. **Invalid: abstract interpretation with only final types**
   ```yaml
   # INVALID - abstract interpretation requires extensible types
   allowSubtypesOf:
     abstractSupertypes:
       nodeTypes:
       - final:  # ERROR: Cannot use final types in abstract interpretation
           nodeType:
             typeLabel: Company
   ```

### Validation Rules

The JSON Schema enforces:

1. **Final types cannot be subtyped**
   - Any type with `extends: FinalType` is invalid

2. **Sealed hierarchies are closed**
   - No types outside the sealed block can extend types within it

3. **Abstract interpretations require extensibility**
   - `allowSubtypesOf` with `abstractSupertypes` is invalid if:
     - All element types are `final:`, OR
     - All element types are in a `sealed:` hierarchy
   - Rationale: Abstract interpretation means "proper subtypes only", but final/sealed types have no subtypes

4. **Sealed implies final on leaves**
   - Leaf types in a sealed hierarchy are implicitly final
   - Intermediate types in sealed hierarchy can still be extended within the hierarchy

**Subtype Relation Properties (Armstrong's Axioms):**

The subtype relation (`<:`) in LEX-2026 satisfies:
- **Reflexive**: Every type is a subtype of itself (`T <: T`)
- **Transitive**: If `A <: B` and `B <: C`, then `A <: C`

These properties ensure consistent type hierarchy semantics and enable:
- Type compatibility checking
- Property inheritance resolution
- Validation of type hierarchies

**Edge Type Subtyping:**

An edge type `S` is a subtype of edge type `T` (`S <: T`) if:

1. **Property Types**: S's properties are a subtype of T's properties (structural subtyping)
2. **Endpoint Node Types**: S's endpoints are subtypes of T's endpoints:
   - **DIRECTED**: `S.source <: T.source` AND `S.destination <: T.destination`
   - **UNDIRECTED**: Endpoints match in either order
3. **Direction**: Must be compatible (DIRECTED <: DIRECTED, UNDIRECTED <: UNDIRECTED)
4. **Self-loops**: SAME endpoint requires special handling

Examples:
```python
# Covariant in endpoint types
KNOWS(Employee, Employee) <: KNOWS(Person, Person)

# Subtype in edge type hierarchy
CLOSE_FRIEND(Person, Person) <: KNOWS(Person, Person)

# Combined
CLOSE_FRIEND(Employee, Employee) <: KNOWS(Person, Person)
```

## Implementation Classes

All interfaces have corresponding implementation classes:

- `CatalogImpl` implements `Catalog`
- `GraphSchemaImpl` implements `GraphSchema`
- `GraphTypeImpl` implements `GraphType`
- `NodeTypeImpl` implements `NodeType`
- `EdgeTypeImpl` implements `EdgeType`
- `PropertyTypeImpl` implements `PropertyType`
- `GraphImpl` implements `Graph`
- `ConstraintImpl` implements `Constraint`
- `StorageSchemaImpl` implements `StorageSchema`

## Usage Examples

### Example 1: Load and Navigate SNB Schema

```python
from grasch.api import GraphSchemaImpl

# Load SNB schema
schema = GraphSchemaImpl.fromYAML("snb-lex-2026.0.3.2-schema.yaml")

# Get graph type
graph_type = schema.getGraphType()

# Find Person node type
person = graph_type.findNodeType("Person")
print(f"Person has {len(person.getPropertyTypes())} properties")

# Find Message hierarchy
message = graph_type.findNodeType("Message")
if message.isAbstract():
    print("Message is abstract")

post = graph_type.findNodeType("Post")
print(f"Post extends: {post.getSupertypes()}")
```

### Example 2: Iterate Through Catalog

```python
from grasch.api import CatalogImpl

# Load catalog
catalog = CatalogImpl.fromYAML("catalog.yaml")

# Iterate through all schemas
for schema in catalog.getGraphSchemas():
    print(f"Schema: {schema.getPathName()}")
    graph_type = schema.getGraphType()
    print(f"  Node types: {len(graph_type.getNodeTypes())}")
    print(f"  Edge types: {len(graph_type.getEdgeTypes())}")
```

### Example 3: Access Constraints

```python
# Load schema
schema = GraphSchemaImpl.fromYAML("snb-schema.yaml")

# Get all constraints
constraints = schema.getConstraints()

for name, constraint in constraints.items():
    print(f"{name}:")
    print(f"  Subject: {constraint.getSubject()}")
    print(f"  Pattern: {constraint.getConstraintPattern()}")
    print(f"  Properties: {constraint.getUniqueKeyComponentPropertyNames()}")
```

## Design Principles

1. **Immutability**: All objects are immutable after construction
2. **Lazy Loading**: Import resolution happens on demand
3. **Type Safety**: Strong typing with Python type hints
4. **Navigation**: Easy traversal of object hierarchies
5. **YAML-First**: Primary construction method is from YAML
6. **Validation**: All objects validated against JSON Schema on construction
